# Lux3D 素材接入

## 运行

```sh
npm ci
npm run dev
```

浏览器访问命令显示的本地地址。源码 `index.html` 需要 Vite。

```sh
npm run build
```

构建同时生成普通网站 `dist/index.html` 和独立游戏 `dist/royale-offline.html`。
后者约 56 MB，可直接双击打开，模型、纹理、脚本和样式均内嵌，使用系统字体，无需服务器和网络。后续修改素材或代码后重新构建即可。

## 已接入的内容

使用已交付的 Lux3D/Blender 素材，生成 30 个运行时 GLB（约 40 MB），纹理最大边 512 像素，未简化几何。来源副本和文件摘要见 `public/models/lux3d/manifest.json`。

| 内容 | 游戏表现 |
| --- | --- |
| 底座、半场、河床、桥、围墙、旗帜、植物和岩石 | 以游戏 `arena.ts` 的 18×32 格、2 格河宽、桥中心 3.5/14.5 重新布局 |
| 红蓝公主塔、国王塔 | 挂接真实塔实体，血条高度按模型包围盒计算 |
| 红蓝骑士、弓箭手、巨人、哥布林、炸弹人 | 替换对应卡牌模型，按移动/攻击目标转向，炸弹人附带炸弹 |
| 加农炮、箭、炸弹、炮弹 | 对应建筑与实际投射物实体 |
| 两种废墟、碎块 | 塔销毁时切换，重开时清除 |

其余兵种继续使用原有 Kenney/程序化表现，新素材加载失败时回退到原模型。模型预加载完成后才开始对局计时。新角色为静态网格，只有整体移动/攻击反馈，没有新增骨骼动画。

展示场景没有直接整体嵌入游戏，因此没有多余演示士兵或重复的静态塔。未更改圣水、卡牌、伤害和寻路规则。相机按窗口比例调整，为顶部 HUD 和底部手牌留出空间。

## 检查与重新生成

```sh
npm test
npm run test:e2e
```

包含模型摘要与内嵌资源检查、实例材质隔离、模型朝向、废墟切换、桥位对齐、浏览器拖拽/重开/缺失模型回退，以及 `file://` 断网模式部署。

需要重新转换素材时，以已交付的 `assembly/game-assets` 为输入：

```sh
blender --background --factory-startup --python-exit-code 1 \
  --python scripts/prepare_lux3d_assets.py -- /path/to/assembly/game-assets
```

转换脚本仅改写仓库 `public/models/lux3d` 下的运行时副本，不改动原始模型。
