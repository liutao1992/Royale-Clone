# 战斗机制规格书（MECHANICS.md）

> 本文件是 Royale Clone 的**实现契约**。所有系统（移动、索敌、攻击、塔、部署、圣水、卡牌、胜负）以此为准。
> 卡牌与塔的具体数值见 `docs/CARDS.md`。
>
> **标签约定**
> - `[已核实]` 有公开数据/官方说明支撑
> - `[待校准]` 需要游戏内实测或逐帧对照后才能定稿
> - `[设定]` 复刻项目的工程决定（原版未公开或不做还原的部分）
>
> **数据基准**：当前游戏锦标赛标准（Level 11，等同旧编号 9 级内容强度）

## 1. 坐标系与地图几何

### 1.1 尺度 `[已核实]`

- 竞技场：**18 tiles 宽 × 32 tiles 长**，被河流平分为两个 18×16 半场。
- 1 tile = 1 世界单位。core 层所有距离/速度用 tile 与 tile/s 表示。
- 3D 映射 `[设定]`：tile 平面 `(x, y)` → Three.js 世界 `(x, height, y)`；y 轴向上。

### 1.2 坐标系定义 `[设定]`

- `(0, 0)` 位于**玩家侧左下角**。
- `x ∈ [0, 18]` 从左到右；`y ∈ [0, 32]` 从玩家底线指向敌方底线。
- 玩家半场 `y ∈ [0, 15)`；敌方半场 `y ∈ (17, 32]`。

### 1.3 河流与桥 `[已核实]`

| 元素 | 参数 |
|---|---|
| 河流 | 横贯全宽，`y ∈ [15, 17]`（宽 2 tiles） |
| 左桥 | `x ∈ [2.5, 4.5]`，中心 x = 3.5（宽 2 tiles） |
| 右桥 | `x ∈ [13.5, 15.5]`，中心 x = 14.5（宽 2 tiles） |
| 地面通行 | 地面单位仅能通过桥跨河；空中单位直线飞行 |

### 1.4 塔位 `[已核实 + 待校准]`

| 塔 | 尺寸 | 玩家侧中心 | 敌方侧中心 |
|---|---|---|---|
| 左公主塔 | 3×3 | (3.5, 6.5) `[待校准]` | (3.5, 25.5) |
| 右公主塔 | 3×3 | (14.5, 6.5) `[待校准]` | (14.5, 25.5) |
| 国王塔 | 4×4，距底线 1 tile | (9, 3) | (9, 29) |

- 对称关系：敌方塔位由玩家侧沿 `y = 16` 镜像。
- 公主塔正对桥中心（x 对齐）。
- 塔的碰撞半径：公主塔 1.0 tile，国王塔 1.4 tiles `[已核实]`。
- 塔的 y 坐标（6.5 / 3）为初始值，进 Stage 1 用截图比对校准 `[待校准]`。

### 1.5 分层 `[设定]`

- 实体层级：`ground`（地面部队、建筑、塔）与 `air`（空中部队、投射物）。
- 地面单位之间互相碰撞；空中单位忽略地面碰撞体积（沿空中通道移动），但可被指定对空的攻击命中。
- 空中单位不与河流交互，直线飞行。

## 2. 对局时间轴 `[已核实]`

总时长最多 5:00（常规 3:00 + 加时 2:00）。

| 阶段 | 时间 | 圣水 | 结束条件 |
|---|---|---|---|
| 常规时间 | 0:00 → 2:00 | 正常（1 / 2.8s） | — |
| 常规时间·双倍 | 2:00 → 3:00 | 双倍（1 / 1.4s） | — |
| 常规结束 | 3:00 | — | 皇冠多者胜 |
| 加时 | 3:00 → 5:00 | 三倍（约 1 / 0.933s） | 先摧毁任意塔者胜（sudden death） |
| 决胜（tiebreaker） | 加时结束后 | — | 结算塔血量自动对耗（见 §12） |

- **三冠（摧毁国王塔）在对局任意时刻立即结束**。
- 常规时间结束时若皇冠数相同 → 进入加时；若不同 → 直接结算。
- 加时内摧毁任意一座塔立即获胜。

## 3. 圣水系统 `[已核实]`

| 参数 | 值 |
|---|---|
| 开局圣水 | 5 |
| 上限 | 10（达到上限后停止累积） |
| 基础速率 | 1 点 / 2.8s |
| 双倍阶段 | 1 点 / 1.4s |
| 三倍阶段 | 1 点 / 0.933s（约 0.9s） |

- 圣水以连续量存储（浮点），UI 显示向下取整的整数滴与当前滴的填充进度。
- 圣水不足的卡牌在 UI 上灰显且不可拖拽 `[设定]`。
- 圣水增长仅在 `matchState = playing` 时推进。

## 4. 实体数据模型 `[设定]`

所有战斗实体（部队/建筑/塔/投射物）共享的统一字段：

```
Entity {
  id, team, kind, cardId        // kind: troop | building | tower | projectile
  position: Vec2                // tile 坐标
  layer: ground | air
  radius: number                // 碰撞半径（tiles）
  mass: number                  // 推挤权重
  hp, maxHp                     // 护盾等扩展预留
  speed: number                 // tiles/s（建筑为 0）
  sightRange: number            // tiles
  attackRange: number           // tiles
  hitSpeed: number              // 秒/次
  loadTime: number              // 首攻预装填时间（秒）
  damage, areaDamage, areaRadius // 攻击与溅射
  targets: ground | air | both  // 可攻击的层级
  targetType: any | buildings   // 建筑目标单位用 buildings
  projectileSpeed?: number      // tiles/min；undefined = 近战
  state: idle | moving | attacking | deploying | dying
  currentTarget?: Entity
  attackTimer, deployTimer, lifetime
}
```

状态机：

```
deploying(1s) → idle/moving → attacking ⇄ moving → dying
                   ↑___________|（目标死亡/丢失时重索敌）
```

- **建筑**：`speed = 0`，有 `lifetime`，部署完成后持续损血（自然流逝 = maxHp / lifetime）。
- **塔**：不可移动、无 lifetime、初始 `inactive`（国王塔）。

## 5. 移动系统

### 5.1 速度档位 `[已核实]`

| 档位 | tiles/min | tiles/s |
|---|---|---|
| Slow | 45 | 0.75 |
| Medium | 60 | 1.0 |
| Fast | 90 | 1.5 |
| Very Fast | 120 | 2.0 |

### 5.2 移动目标决策（每 tick） `[已核实]`

1. 若存在合法 `currentTarget` → 朝其移动；进入 `attackRange` 后停止并转入攻击。
2. 若无 `currentTarget` 且视野内无合法目标 → 朝**目标建筑**移动：
   - `targetType = buildings` 的单位：最近的敌方建筑/塔。
   - 普通单位：最近的敌方塔（同侧或跨河时按 §5.3 过桥）。
3. 若视野内出现合法目标 → 索敌（见 §6）并朝其移动。

### 5.3 过河寻路 `[已核实 + 设定]`

- 单位与目标的相对位置决定路径：
  - 同侧 → 直线前往。
  - 跨河 → 必须先前往**桥的入口点**，过桥后再前往目标。
- 桥选择：优先选择与自身 lane 同侧的桥；若另一桥显著更近则重新选择 `[待校准]`。
- 桥通行：桥宽 2 tiles，多个单位在桥口形成排队/拥堵，依靠分离力自然挤过（§5.4）。
- 跳跃单位（Hog Rider）可直接跨河，不经过桥 `[已核实]`。触发条件与轨迹 `[待校准]`。

### 5.4 碰撞与推挤 `[已核实]`

- 所有地面单位使用圆形碰撞体（半径见 `CARDS.md`）。
- 重叠时的分离解算（separation）：按质量加权分配推开距离。
- 推挤权重：质量差 + 速度差共同决定 `[已核实：官方隐藏机制]`。
- 桥梁与塔身是硬碰撞体；塔不可被推动。
- 单位不会被推入河中 `[设定]`（地面单位）；被挤压路径按沿桥方向滑动处理。

### 5.5 到达判定 `[待校准]`

- 攻击停止距离的判定以**碰撞半径边缘**为准（中心距 ≤ attackRange + 双方半径之和的修正方式待实测）。

## 6. 索敌与仇恨

### 6.1 视野（Sight Range） `[已核实]`

- 大部分部队：**5.5 tiles**；Musketeer 6；Archers 5.5。
- 建筑目标单位视野更长：Giant 7.5；Hog Rider 9.5。
- 建筑：视野 = 攻击射程。
- 塔：视野 = 攻击射程（公主塔 7.5 / 国王塔 7）。

完整对照表见 `docs/CARDS.md §隐藏属性表`。

### 6.2 搜索规则 `[已核实]`

- 无目标时，在 `sightRange` 内搜索**最近**的合法目标（层级与 targetType 双重过滤）。
- 距离按实体位置（中心）计算 `[待校准]`（碰撞半径是否计入待实测）。
- 若视野内无合法目标，则向目标建筑前进（§5.2），途中持续扫描。

### 6.3 锁定与重索敌 `[已核实]`

- **锁定后不主动切换目标**，即使出现更近的敌人。
- 重索敌触发条件：
  1. 当前目标死亡；
  2. 当前目标离开视野范围（追击中超出一段 leash 距离）`[待校准]`；
  3. 自身被眩晕/击退（Zap、Fireball 真眩晕）；
  4. 当前目标不再合法（如对空单位攻击目标起飞等边缘情况）。
- 攻击中的单位被外力推出射程 → 重新追击/索敌。

### 6.4 建筑目标单位（Building-targeter） `[已核实]`

- Giant / Hog Rider：`targetType = buildings`，**永远不攻击部队**。
- 被敌方部队物理阻挡时：不反击，仅推挤/等待（依靠质量优势挤开或绕行）。
- 会受建筑（Cannon）吸引：建筑进入视野即锁定。

### 6.5 塔索敌 `[已核实]`

- 塔自动攻击射程内**最近**的合法目标（对空 + 对地）。
- 不主动换目标，直到目标死亡或离开射程。

## 7. 攻击系统

### 7.1 攻击流程 `[已核实]`

```
进入射程 → 起手（首攻时间） → 命中事件 → 冷却（hitSpeed） → 下一次命中
```

- **首攻时间 = hitSpeed − loadTime**（部署/行走时预装填；部署落地即视为已装填）。
- 命中事件在动画的固定帧触发（Stage 4 用 AnimationMixer 事件绑定）。
- 每次攻击的冷却按 hitSpeed 从命中事件起算。

### 7.2 命中判定 `[设定 + 待校准]`

- 近战：命中事件时检查目标仍在 `attackRange`（含容忍量）内，则结算伤害。
- 远程：命中事件时生成投射物（§8），伤害在投射物命中时结算。
- 目标在投射物飞行途中死亡：投射物飞向原目标位置后消散 `[待校准]`。

### 7.3 伤害类型 `[已核实]`

| 类型 | 说明 | 本 roster 示例 |
|---|---|---|
| 单体 | 只结算主目标 | Knight、Musketeer、Giant |
| 范围（溅射） | 以落点为中心 `areaRadius` 内全体 | Valkyrie（2.0）、Bomber（1.5）、Baby Dragon（1.5）|
| 法术 | 区域结算 + 特效（眩晕/击退） | Fireball、Arrows、Zap |

- 无敌方误伤（友军不受伤害）`[已核实]`。
- 对塔伤害：部队与建筑全额；法术按各自的对塔伤害值（见 `CARDS.md`）。

### 7.4 眩晕与击退 `[已核实]`

- Zap：眩晕 0.5s；中断攻击动画、重置蓄力、打断目标锁定（重索敌）。
- Fireball：真眩晕 + 击退 1 tile；同样会重置攻击动画。

### 7.5 死亡处理 `[设定]`

- HP ≤ 0 → `dying` 状态，播放死亡动画后从模拟移除（移除前不参与索敌与碰撞）。
- 本 roster 无死亡伤害卡牌（预留字段）。

## 8. 投射物与法术系统

### 8.1 投射物 `[已核实 + 待校准]`

- 远程攻击与有弹道的法术均为场景实体。
- 速度表（tiles/min）见 `docs/CARDS.md`。
- 追踪方式：投射物朝目标位置飞行；是否预判移动目标 `[待校准]`。
- 命中：到达目标点后结算伤害/溅射，播放命中特效。

### 8.2 法术分类 `[已核实]`

| 法术 | 弹道 | 半径 | 特殊 |
|---|---|---|---|
| Zap | 瞬发，无弹道 | 2.5 tiles | 眩晕 0.5s |
| Fireball | 弹道 600 tiles/min | 2.5 tiles | 击退 1 tile + 真眩晕 |
| Arrows | 弹道 1100 tiles/min，3 波依次落下 | 3.5 tiles | 分波结算 |

- 法术可放置在竞技场任意位置（含河道上空）`[已核实]`。
- 法术对塔伤害为独立数值，不按比例自动计算（见 `CARDS.md`）。

## 9. 塔系统

### 9.1 数值 `[已核实]`

见 `docs/CARDS.md §塔数值表`（公主塔 3052 HP / 109 伤害 / 0.8s / 7.5 射程；国王塔 4824 HP / 109 伤害 / 1.0s / 7 射程，L11 基准）。

### 9.2 攻击行为 `[已核实]`

- 公主塔：对局开始即激活，自动索敌（空 + 地）。
- 国王塔：初始 `inactive`；**被任意伤害命中或己方任意公主塔被摧毁**后激活，开启攻击。
- 塔的投射物速度：公主塔 600、国王塔 1000 tiles/min `[已核实]`。

### 9.3 塔的摧毁 `[已核实]`

- 摧毁公主塔：对方获得 1 皇冠；己方该侧部署区扩展（§10.2）；己方国王塔激活（若未激活）；该位置变为可通行废墟。
- 摧毁国王塔：对局立即结束（3 皇冠）。

### 9.4 法术对塔减免 `[已核实]`

- 每个伤害法术拥有独立的对塔伤害值（Fireball 207、Arrows 93、Zap 58，L11 快照值）。
- 部队攻击塔无减免。

## 10. 部署系统

### 10.1 部署流程 `[已核实]`

```
按下卡牌 → 拖拽 → 显示部署范围 + 单位预览（合法绿 / 非法红）
→ 松开 → 落地 → 部署时间 1s → 进入战斗
```

- 部署时间：1s（部署中不可移动/攻击，可被法术命中）`[已核实]`。
- 部署落点：以拖拽位置为中心放置（多单位卡按固定阵型展开，如 Archers 横排、Goblins 方阵）`[已核实 + 待校准]`。
- 拖拽到非法位置时不可释放（卡牌回手）`[设定]`。

### 10.2 合法区域 `[已核实 + 待校准]`

| 区域 | 规则 |
|---|---|
| 己方半场 | `y < 15`（河缘为止），排除塔身与建筑占位 |
| 破塔扩展（pocket） | 摧毁对方某侧公主塔后，敌方半场**同侧**过桥后的矩形区域解锁 |
| 法术 | 全场任意位置（含河道），无区域限制 |

- pocket 的精确 tile 范围 `[待校准]`：初始实现取「对应 lane 半场宽、纵深约 5 tiles」的矩形，进 Stage 2 用游戏录像校准。

### 10.3 非法位置 `[设定]`

- 河面、塔身、场上建筑占位、对手未解锁半场、超出边界。

## 11. 卡牌与手牌循环 `[已核实]`

- 卡组 8 张，手牌 4 张，下一张预览 1 张。
- 打出某张手牌后：
  - 该卡进入**队列尾部**；
  - 下一张卡补入手牌；
  - 新的"下一张"从队列头显示。
- 循环是严格 FIFO：`手牌 → 使用 → 队尾 → 等待再次入手`。
- 圣水不足时卡牌灰显、不可拖拽。
- 打出后手牌位置立即补位；下一张预览同步更新。

## 12. 胜负系统 `[已核实]`

| 事件 | 结果 |
|---|---|
| 国王塔被摧毁（任意时刻） | 立即 3 皇冠获胜 |
| 常规时间结束，皇冠数不同 | 皇冠多者胜 |
| 常规时间结束，皇冠数相同 | 进入加时 |
| 加时内任意塔被摧毁 | 摧毁者立即获胜 |
| 加时结束仍无塔被毁 | 进入决胜（tiebreaker） |
| 决胜 | 所有部队移除；双方塔同步快速掉血，先被摧毁的一方落败 |
| 决胜时双方塔血量完全相等 | 平局（跳过决胜） |

- 皇冠计数：每摧毁一座公主塔 +1，国王塔 +3 且立即结束。

## 13. AI 决策规则（Stage 3 细化）

本章为框架占位，进入 Stage 3 时展开为完整决策树：

- **防守响应**：识别威胁单位（坦克/群兵/远程），选择克制卡牌与落点。
- **圣水管理**：低圣水（< 4）保守、高圣水（≥ 8）推进。
- **进攻时机**：对方圣水空窗、兵线推进时反打。
- **难度参数**：反应延迟（0.5–1.5s）、失误率、卡牌选择权重。

要求的决策输出：`{ cardId, deployPosition, timestamp }`。
